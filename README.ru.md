# WindowManager

WindowManager — macOS-приложение на SwiftUI + AppKit, работающее из Menu Bar, для сохранения и восстановления раскладок окон на одном или нескольких дисплеях. Оно подходит, если нужно вернуть окна уже запущенных приложений после изменения конфигурации экранов — вручную или через Auto-apply.

> Английская версия: [`README.md`](README.md)

## Что делает приложение

- Показывает текущую конфигурацию дисплеев: количество, основной дисплей, геометрию и scale.
- Захватывает окна запущенных обычных приложений через Accessibility API. Окна меньше 50×50 points и окна вне объединения текущих дисплеев пропускаются.
- Сохраняет метаданные окон, используемые при восстановлении:
  - имя приложения и необязательный bundle identifier;
  - заголовок, Accessibility role и subrole;
  - абсолютный `CGRect`;
  - нормализованный `relativeFrame`;
  - наблюдаемый ID дисплея, геометрию, visible frame, scale и legacy-индекс;
  - время захвата.
- До первого подтверждённого импорта хранит раскладки в `UserDefaults` (`SavedLayouts`); затем использует приватный транзакционный файл в Application Support. Исходное значение остаётся резервным снимком; синхронизации и удалённого хранилища нет.
- Восстанавливает frame окон через `AXUIElementSetAttributeValue`, затем читает позицию и размер обратно и сообщает фактический результат.
- Поддерживает Menu Bar-действия: применить раскладку, сохранить текущую, переключить Auto-apply, открыть главное окно и выйти.
- Отслеживает изменения конфигурации экранов и может автоматически применить наиболее недавно использованную подходящую раскладку.

## Основные сценарии использования

### 1. Первичная настройка разрешений

Для захвата и восстановления окон приложению нужны разрешения macOS:

1. **Accessibility** — чтение и управление позициями окон.
2. **Screen Recording** — эвристическая проверка через доступ к списку видимых окон.

Откройте:

- `System Settings → Privacy & Security → Accessibility`
- `System Settings → Privacy & Security → Screen Recording`

Добавьте WindowManager в оба списка и перезапустите приложение, если macOS попросит это сделать.

### 2. Сохранение раскладки

1. Расставьте окна уже запущенных приложений.
2. Нажмите **Save Current Layout** в главном окне или выберите **Save Current Layout...** в Menu Bar.
3. Проверьте найденные окна: маленькие и находящиеся вне дисплеев могут быть пропущены.
4. Введите имя раскладки.
5. Нажмите **Save Layout**.

### 3. Восстановление раскладки

- В главном окне нажмите кнопку восстановления у нужной раскладки.
- Или выберите имя раскладки в Menu Bar-меню.

Для каждой сохранённой цели приложение ищет запущенное приложение по сохранённому bundle identifier; цели без bundle identifier используют fallback по локализованному имени. Поэтому цель с bundle identifier требует совпадения текущего bundle identifier. Текущие AX-окна приложения читаются один раз и сопоставляются по заголовку, role, subrole и метаданным frame. Динамические заголовки и изменившийся набор окон могут помешать сопоставлению.

Resolver дисплеев предпочитает уникальный пригодный наблюдаемый ID, затем дисплей, содержащий центр сохранённого frame, сохранённый индекс и, наконец, первый дисплей в детерминированном порядке. Абсолютный frame без пересчёта используется только при полном совпадении сохранённых и текущих display frame, visible frame и scale. Иначе конечный frame строится из конечного нормализованного `relativeFrame`; для старых раскладок возможен fallback к сохранённому абсолютному frame. Обычные frame зажимаются так, чтобы полезная полоса title bar оставалась доступной, без незаметного уменьшения сохранённого размера. Fullscreen/maximized-представления могут отключить этот clamp.

Результат восстановления основан на AX-записи и read-back. Возможны, например, статусы `positionSet`, `appImposedClamp`, `axFailure`, `restoreSuperseded`, `coordinateUnavailable`, `appNotFound` и `windowSkipped`. В число восстановленных окон входит только `positionSet`.

### Экспорт резервной копии

В разделе **Saved Layouts** нажмите **Export Backup…**, прочитайте предупреждение о конфиденциальности и выберите локальный файл. JSON содержит **все** раскладки, включая заголовки окон, имена приложений, геометрию, метаданные дисплеев, ID и даты ISO-8601. Храните файл конфиденциально: приложение никуда его не отправляет. Пустой список сохраняется как `[]`. Отмена не затрагивает файл; ошибка экспорта не меняет сохранённые раскладки. Формат совместим с существующим `[Layout]`, но импорта и восстановления из файла пока нет.

### 4. Автоматическое применение

После изменения конфигурации экранов Auto-apply ждёт стабильную топологию перед записью frame:

- событие debounce — 0,5 секунды;
- снимок дисплеев опрашивается каждые 0,25 секунды;
- нужны три одинаковых последовательных снимка, включая геометрию и scale;
- если стабильность не достигнута за 10 секунд, попытка пропускается;
- сопоставление использует ID экранов и, если геометрия есть в обеих конфигурациях, полное равенство `ScreenConfiguration`;
- выбирается наиболее недавно использованная подходящая раскладка; неиспользованные идут после использованных;
- отсутствующие приложения и окна повторяются не более трёх раз с интервалом одна секунда;
- изменение топологии или выключение Auto-apply инвалидирует ожидающие retry и предотвращает дальнейшие записи;
- итоговое уведомление отправляется не более одного раза после исходной попытки и активных retry (либо отмены активного retry при выключении Auto-apply), при наличии разрешения macOS на уведомления; отмена из-за изменения топологии удаляет ожидающее уведомление.

Auto-apply включён по умолчанию (ключ `autoApplyEnabled` в `UserDefaults`) и переключается в главном окне или через **Auto-apply Layouts** в Menu Bar.

## Требования

- macOS с поддержкой SwiftUI/AppKit и Accessibility API.
- Xcode.
- Разрешения Accessibility и Screen Recording.

Текущие настройки проекта:

- Target: `WindowManager`
- Scheme: `WindowManager`
- Bundle ID: `obelisk.WindowManager`
- Swift: `5.0`
- Marketing version: `2.9`
- Build: `7`
- macOS deployment target: `26.2`

## Сборка из исходников

```bash
xcodebuild \
  -project WindowManager.xcodeproj \
  -scheme WindowManager \
  -configuration Debug \
  -destination 'platform=macOS' \
  build
```

Release-сборка:

```bash
xcodebuild \
  -project WindowManager.xcodeproj \
  -scheme WindowManager \
  -configuration Release \
  -destination 'platform=macOS' \
  build
```

## Структура проекта

```text
WindowManager/
├── WindowManagerApp.swift          # Точка входа, AppDelegate, инициализация сервисов
├── Info.plist                      # Иконка приложения
├── Models/
│   ├── Layout.swift                # Модель раскладки и конфигурации экранов
│   ├── WindowInfo.swift             # Модель сохранённого окна
│   └── RestoreResult.swift          # Статусы и результаты восстановления
├── Services/
│   ├── WindowService.swift         # Захват и восстановление окон через AX API
│   ├── FrameRestoreEngine.swift    # AX-запись, паузы, drift correction, read-back
│   ├── ScreenResolver.swift        # Выбор дисплея и расчёт frame
│   ├── WindowAssignment.swift       # Сопоставление текущих окон
│   ├── LayoutStorageService.swift  # Координация старого и нового хранилища
│   ├── PermissionsService.swift    # Проверка/запрос разрешений macOS
│   ├── ScreenMonitorService.swift  # Auto-apply со стабильной топологией
│   └── StatusBarService.swift      # Menu Bar-интеграция
└── Views/
    ├── ContentView.swift           # Главное окно
    ├── LayoutListView.swift        # Список раскладок
    ├── RestorePreviewView.swift    # Безопасный предпросмотр восстановления
    └── PermissionsView.swift       # Экран разрешений
```

## Известные ограничения

- Приложения должны быть запущены: WindowManager не запускает отсутствующие приложения.
- Bundle ID, локализованное имя, заголовок, role, subrole и frame улучшают сопоставление, но не гарантируют его. Динамические заголовки и изменившийся набор окон могут помешать назначению.
- Некоторые приложения отклоняют изменения Accessibility, зажимают frame или меняют его после read-back; статус отражает этот результат и не выдаёт его за успех.
- ID дисплеев — ключи текущего наблюдения и могут измениться после переподключения. Нормализованные координаты адаптируют геометрию, но не доказывают, что речь идёт о том же физическом мониторе; vendor/model/serial fingerprint не сохраняется.
- Старые раскладки остаются читаемыми, но без новых метаданных дисплея используют fallback и не могут заявлять точную идентичность дисплея.
- Для захвата и восстановления нужен Accessibility. Screen Recording проверяется эвристически через доступ к списку окон.
- Экспорт и импорт запускаются вручную, локально; синхронизации нет. Импортированные раскладки не участвуют в Auto-apply.
- Автоматизированная проверка не изменяет реальные окна или дисплеи. У scheme WindowManager нет test action, поэтому `xcodebuild test` для этой цели недоступен.
